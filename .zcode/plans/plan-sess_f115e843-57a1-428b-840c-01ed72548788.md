# 双屏对折电子书 · 实施方案 v4（5V 电池包 + 模块 3.3V 供电）

## 已确认的决策
- 主控：**ESP32-S3 N16R8** 开发板（8MB PSRAM + 16MB Flash）
- 屏：GDEY0583T81 **带转接板模块** ×2，FPC 从长边引出 → 两屏镜像安装，排线不跨铰链
- SD 卡：**SDIO / SDMMC 4-bit**（SPI 作 fallback）
- 电源：**成品 5V 充电电池包**直供开发板 5V 脚；**3.3V 从开发板 3V3 脚引出**喂屏/SD/霍尔等模块
- 软件：自研 Arduino 分层，**P3 先 TXT、P4 再 EPUB**；P2 阶段对照 Diptyx 固件验证双屏刷新
- 结构：**不做统一 PCB**，成品模块 + 手工排线 + **3D 打印底板**；只自制按键小板
- 开合检测：**DRV5032 霍尔模块** + 磁铁 → 合盖深睡、开盖唤醒

## 1. 硬件

### 1.1 模块清单（全部成品）
| 模块 | 规格 | 说明 |
|---|---|---|
| 主控 | ESP32-S3-DevKitC-1 N16R8 | 8MB OPI PSRAM 是硬需求 |
| 屏 ×2 | GDEY0583T81 转接板模块 | 排针期用面包板；装机随屏固定 |
| SD | microSD 模块（SDIO/SPI 双模） | 接 SDMMC 4-bit |
| 电池 | **成品 5V 充电电池包** | 见 1.4 选型硬指标 |
| 霍尔 | DRV5032 模块 + 小磁铁 ×1 | 各贴一半 |
| 按键 | 自制小板 ×1（4 键） | 唯一自制件 |
| 底板 | **3D 打印** ×2 + 胶带/硅胶铰链 | |

（原 TP4056/MP1584 已按新供电方案取消；AMS1117-3.3 仅作"双屏重启"时的回退备件，先不买。）

### 1.2 引脚分配（S3，避开 strapping 0/3/45/46、USB 19/20、八线 PSRAM 占用的 33-37）
```
墨水屏（SPI2，两屏共用 SCK/MOSI）：
  SCK 12, MOSI 11
  左屏：CS 14, DC 15, RST 16, BUSY 17
  右屏：CS 18, DC 21, RST 47, BUSY 48
SD 卡（SDMMC 4-bit 独立外设）：
  CLK 38, CMD 39, D0 40, D1 41, D2 42, D3 13
按键（RTC GPIO，可 ext1 唤醒）：
  PREV 1, NEXT 2, MENU 9, FONT 10   （内部上拉，低有效）
霍尔 DRV5032 OUT：4
电池电量检测：5V 电池包若自带电量指示灯则省掉 ADC；否则 5V 分压进 GPIO 8（ADC1_CH7）
备用：5, 6, 7
```

### 1.3 SD 为什么走 SDIO
- **快一个量级**：SDIO 4-bit 20MB/s+，SPI 实际几 MB/s，EPUB 解压、分页缓存、字库查表都受益
- **不占 SPI 总线**：SDMMC 独立外设，屏的 SPI2 刷新时读卡零阻塞（atomic14 挂同总线是一串 issue 的根源）
- **Fallback**：core 2.0.17 的 SDMMC 库在 S3 上若不稳，模块切 SPI 模式接 SPI3，应用层 `storage/` 接口不变

### 1.4 电源（新方案 + 两个硬指标）
```
5V 电池包 → 开发板 5V/VIN 脚
开发板 3V3 脚 → 屏L/屏R VCI（各加 100µF+100nF 就近去耦）、SD 模块、DRV5032、按键上拉
```
**电池包选型两条硬指标：**
1. **必须无自动关机/支持常开**——ESP32 深睡整机仅几十 µA，普通充电宝会在低电流下自动断电，之后按键/霍尔都唤不醒，合盖深睡功能直接报废。买前确认规格书或实测
2. 容量 3000mAh 级即可（阅读时整机约 100-200mA，深睡 µA 级，待机按月计）

**双屏电流尖峰预案**：两块屏重叠刷新时升压同时抽电，峰值 300-400mA，叠上 ESP32 可能顶垮开发板 LDO 导致重启。缓解：每屏大电容去耦 + WiFi 默认关。若 P2 实测仍重启 → 5V 电池包后加一块 AMS1117-3.3 模块单独喂双屏（回退方案，仍全是成品模块）。

深睡时**屏 VCI 保持供电**（DSLP 约 1µA），唤醒直接差分刷新，不等 3s 全刷。

### 1.5 霍尔传感器与开合逻辑
DRV5032 推挽输出全极性开关，微安级，深睡保持供电。
- 磁铁右半、传感器左半（或反之），合盖正对
- **开盖** → OUT 翻转 → GPIO4 ext1 唤醒 → SD 读进度 → 差分刷新恢复两页
- **合盖** → 显示"封面页"（书名/进度/时间）→ 深睡
- 按键（1/2/9/10）与霍尔共用 ext1，任意触发即醒
- 买**全极性开关型**；误买锁存型则唤醒逻辑改"任一沿都醒"

### 1.6 结构装配（3D 打印底板）
- 左半底板：屏L+转接板、S3 开发板、SD 模块、按键小板、霍尔；电池包嵌在左半或脊部（重量均衡考虑，建议脊部附近）
- 右半底板：屏R+转接板、磁铁
- 两半之间 **10 芯排线**（SPI 四信号 + 3V3 + 地）过铰链
- 铰链：布基胶带起步（Diptyx 硅胶活铰链思路），视效果再打印一体铰链件
- 屏镜像安装（右屏旋 180°），FPC 朝外侧
- 打印建议：PLA/PETG 均可，底板 2-3mm 厚 + 加强筋；注意转接板排针高度给线槽留空间
- 单页有效区 88.2×118.8mm（≈A6），展开 176×119mm；整机约 196×129mm，合起约 98×129mm

## 2. 软件架构

沿用 atomic14 分层（替掉它的双屏盲区、字体硬伤、刷新策略）：

```
ui/        BookList / Reader / Menu          ← 4键状态机
epub/      (P4) Epub → Zip(miniz) → HtmlParser → Blocks
layout/    TextBlock(断行) / Paginator / 页缓存
render/    DualEink → EinkPanel ×2
font/      GlyphProvider (Latin点阵 | Unifont-CJK)
storage/   SD(SDMMC) / progress / page cache
power/     霍尔/按键唤醒、深睡、电量
```

### 2.1 驱动层重构（P1 核心）
先修现状两个硬伤：`EPD_SPI.h` 引脚写死成 A14-A17 宏（无法驱动两块屏）、`lcd_chkstatus()` 无超时死循环（接线抖动即挂死）。重构成：

```cpp
class EinkPanel {
  EinkPanel(int cs, int dc, int rst, int busy, bool mirrored);
  bool begin();                          // false = BUSY 超时
  bool showDiff(const uint8_t* prev, const uint8_t* next);  // DTM1 写真实上一帧
  bool trigger();                        // DRF(0x12)，不等待
  bool waitIdle(uint32_t ms);            // 带超时 + vTaskDelay(1) 喂狗
  void setSpeed(Full|Fast|Partial);      // 三档 = 0x00 PSR + 0x50 CDI + 0xE5 强制温度
  void sleep(); void wake();
};
```

三处必须改对：
1. **引脚作参数**，单类实例化左右两屏
2. **`waitBusy` 带超时**
3. **DTM1(0x10) 写真实上一帧而非 0xFF**。vendor 代码灌全白 = 控制器以为屏本是白的，该擦的像素不被驱动——残影就是这么来的。上一帧存 PSRAM（38880B/屏），是翻页不闪不残影的关键

### 2.2 双屏刷新：重叠刷新（P2，对照 Diptyx 验证）
```
DualEink::present(fbL, fbR):
  1. 等两屏 idle
  2. 屏L: DTM1+DTM2 → DRF，不等待
  3. 利用屏L busy 的 ~1.5s 给屏R 灌数据 → DRF
  4. 等两屏都 idle
```
3s 串行 → ≈1.6s 重叠。代价是两屏升压同时工作（1.4 的电流尖峰预案因此存在）。Diptyx 的 `InitNormalBoth/DisplayPictureBoth/WaitUntilIdleBoth` 就是这套 API 形状，P2 直接拿它对表；`partialUpdatesRemaining[2]` 每屏独立残影计数、左右分存 VCOM 也一并参考。

### 2.3 字体与排版（原版最大的坑，第一天就处理）
atomic14 的 issue #28/#75/#90 全是字体，根因是**排版链路 byte-oriented**——按 char 切词，中日韩全变 `?`。所以：
- **UTF-8 在分词处就解码**，绝不字节索引
- 拉丁：fontconvert.py 生成点阵；CJK：**Unifont**（全 BMP，16×16，约 2MB）存 SD 卡流式查表（照抄 The Open Book 的 Babel：`.bin` + 索引表）
- 断行：拉丁用动态规划（Knuth-Plass 风格），CJK 按字符断 + 避头尾；混排时 CJK 字符当独立"词"
- 分页：**绝不在 MCU 上排整本书**（The Open Book 实测一本小说 20 分钟且会崩）。按章排版，结果缓存 SD（`/<bookhash>/sections/NNN.bin`，带排版参数哈希失效）

### 2.4 TXT 先行（P3）与 EPUB（P4）
- P3：纯 UTF-8 TXT 阅读器（GBK 顺手转），第一行当书名——The Open Book 约定，直接兼容
- P4：miniz(MIT) 解压 + tinyxml2(**锁版本**)；`META-INF/container.xml`→opf(spine)→逐章 XHTML；CSS 忽略、标签白名单；**分块流式解析**（atomic14 issue #73：>280KB 章节崩分配器，先解压到 SD 临时文件再流式喂）
- .mobi 书库用 Calibre 在电脑上转 EPUB 作前置步骤
- 许可证：miniz(MIT)+tinyxml2(Zlib) 干净；**不引入 GxEPD2(GPL-3.0)/EPDiy(LGPL-3.0)**

## 4. 已知的坑（按严重程度）
1. **5V 电池包自动关机**——选错电池合盖深睡即报废（见 1.4 硬指标）
2. **双屏同时刷新电流尖峰**——LDO 顶不住会重启；大电容去耦优先，不行加 AMS1117（见 1.4）
3. **双屏 SPI 争用**——严格"选片→传输→释放"，任何提前 return 前先放 CS
4. **整书排版**——绝不在 MCU 上排整本书（The Open Book 最大技术债）
5. **CJK 字体与断行**——见 2.3
6. **EPUB 大章节 >280KB**——必须流式（atomic14 issue #73）
7. **SDMMC 在 core 2.0.17 + S3 的兼容性**——P3 首件事验证，不稳回退 SPI（接口不变）
8. **VCOM 逐屏不一致**——`0x50`(CDI) 左右分开标定（Diptyx 即左右分存）
9. **残影**——每 5 次快刷插一次全刷
10. **`0xE5` 强制温度的副作用**——快波形靠假装高温，对比度略降；后续读面板温度传感器（0x40 TSC/0x43 TSR）补偿
11. **USB 外壳通孔不焊**——会把 USB 座连焊盘撕掉（装配时注意）
